# 项目完成标准与后续路线

更新日期：2026-11-03。此文作为后续范围与验收依据，替代早期六周计划中未完成组件必须全部部署的要求；旧日志保留当时的事实。

## 目标与协作方式

以公开 M5 数据完成门店商品级未来 30 天销量预测，证明算法实验、数据工程、时序建模、MLOps 和结果解释能力。与 RAG Agent System 形成互补，不以增加服务数量或 LLM 技术复杂度衡量完成程度。

继续以教学为主：由学习者实现核心数据、模型、训练与评估代码，助手拆解任务、解释原理、审阅实现和结果。仅在明确委托时由助手代写具体模块；文档整理与必要核查按当前授权进行。

## 当前起点

- 全量基础表 59,181,090 行；固定实验子集 388,200 行，200 条门店商品序列。
- 完整实验特征文件为 `data/feature/sales_feature.parquet`，388,200 行、24 列；训练入口已读取该文件。
- 窗口为 56 天历史、30 天标签，按完整标签窗口划分 Subset，排除跨集合边界窗口。
- Naive 验证 MAE 为 0.954333，验证集包含 200 个窗口、6,000 个目标值。其他指标与模型尚无结果，测试集尚未评估。
- 当前 Dataset 仅返回历史销量与销量标签；24 列不等于 24 个模型输入特征。
- MinIO 与 TensorBoard 已跑通；带优化器的训练接口已实现，尚未通过实际可训练模型验证。

## 固定评估协议

1. 固定当前 100 个共同商品、2 家门店、采样种子和日期边界。模型比较使用同一目标集合，验证与测试各一次预测未来 30 天。
2. 使用验证集选择超参数、特征和最佳 epoch。方案固定后才做测试集比较，测试成绩不用于反复选择模型。
3. MAE 为全部绝对误差之和除以目标值数；RMSE 为全部平方误差的均值再开方；不能平均各批次的 RMSE。
4. WAPE 为 `sum(abs(prediction-target)) / sum(abs(target))`，展示时明确比例或百分数。分母为零时报告未定义及样本量，不能静默加小数后当作正常指标。
5. Naive、Seasonal Naive、LSTM、TFT 优先在完整实验子集比较。ARIMA 若仅覆盖代表序列，单列对照表，并在同一代表序列上补算其他模型指标，不与完整子集指标直接排名。
6. 保存逐序列、逐预测日的结果，至少包含门店、商品、预测起点、标签日期、预测步长、真实值、预测值、模型与 run 标识。

深度模型不必胜出。若没有稳定提升，应检查数据与训练、说明适用范围，如实报告基线的竞争力。

## 多变量输入与信息边界

| 类型 | 候选字段 | 使用边界 |
| --- | --- | --- |
| 历史观测 | 销量、历史价格、lag、rolling | 只取预测起点及之前已知的值 |
| 未来已知 | weekday、month，后续可补已公开的节日或事件日历 | 未来销量派生值不属于这一类 |
| 静态属性 | store、item、category | 编码与未知类别规则可复用 |

先完成一个清楚、可测试的输入约定，再扩展特征。对未知未来价格，默认不使用；只有明确的已知价格计划实验才允许输入，不能仅因离线文件中存在未来价格便认为上线时可知。

价格缺失与零销量不同，保留缺失标记并说明填充策略。拟合缩放器、缺失填充值、类别词表或销量分组阈值时，仅使用训练部分。历史特征必须分序列计算；多步预测中不可读取标签区间真实销量计算未来 lag/rolling。

## 执行顺序

### 1. 建立统一评估与周期基线

补齐 MAE/RMSE/WAPE 的聚合与测试，保留逐目标预测；实现每周重复的 Seasonal Naive，用已知最后一周循环预测 30 天，不能索取验证区间的真实销量。先形成两行真实基线结果。

### 2. 完成 LSTM 训练闭环并接入 MLflow

先用小型单变量 LSTM 检查张量、梯度、损失下降与 checkpoint 加载。完成早停与最佳模型恢复，将 MLflow 接入统一 fit/评估流程，再运行正式实验。保持 Naive 无优化器的分支可复用。

### 3. 扩展多变量输入并完成 TFT

逐步加入历史数值特征、静态编码、未来已知日历；明确缺失与缩放策略。LSTM 与 TFT 均有真实训练结果，其中至少一个使用完整的多变量输入约定。做受控特征对照，不把仅有单变量和多变量的不同架构结果之差全部归因于特征。

### 4. 补 ARIMA 代表性对照与可选 HPO

代表序列选择规则在训练数据上确定并保存，不能根据最终效果挑选。ARIMA 与其他模型在同一代表集合比较。HPO 若实施，固定验证规则、搜索范围、trial 预算、随机种子与剪枝记录，测试集不进入调参目标。

### 5. 固定方案，做最终分析与展示

按验证结果固定配置与 checkpoint 后运行最终测试。误差切片至少包括：

- 品类：FOODS、HOBBIES、HOUSEHOLD。
- 销量水平：按训练期统计确定 high/medium/low 阈值，不能用测试期销量分组。
- 预测步长：Day 1–7、8–14、15–30。

各片报告样本量与统一指标，区分观察到的差异与能够支持的解释。当前仅有一个验证和一个测试起点，不能据此声称跨季节稳定或有统计显著性。event、门店、价格变化为可选附加切片；价格变化不直接等于真实促销。

## MLflow 最小记录

每个正式 run 至少记录：模型、代码版本、数据版本与文件校验标识、采样与日期边界、输入特征、超参数、随机种子、设备、训练耗时、逐轮指标、最佳 epoch、最终 MAE/RMSE/WAPE、checkpoint、预测结果及切片分析。数据文件继续由 MinIO/本地管理，run 记录位置与版本，不要求把全量 Parquet 重复上传为每次实验的 artifact。

## 完成后的冻结条件

- [ ] Naive、Seasonal Naive、ARIMA、LSTM、TFT 均有可复核结果，ARIMA 覆盖范围单独标明。
- [ ] LSTM/TFT 至少一个真正使用多变量特征，具备合理对照与输入可用性说明。
- [ ] 所有对照使用统一 MAE/RMSE/WAPE，验证和最终测试的用途清楚。
- [ ] MLflow 可追溯参数、数据版本、结果和最佳 checkpoint，模型可以加载复现预测。
- [ ] 品类、销量水平和预测步长三类误差分析完成，结论有数据支撑。
- [ ] README 展示问题、架构、数据、模型结果、主要发现、局限及复现命令。

满足以上条件即冻结功能范围，转入面试准备。HPO、Airflow 或额外服务不阻塞冻结，也不因 TFT 没有胜出而无限调参。

20–30 个有效小时仅是尚未验证的粗略预算，不作交付承诺。完成首个 LSTM 端到端实验后，根据实际训练耗时、依赖兼容、多变量改造和 TFT 接入成本重新估计；计划按验收结果推进。
