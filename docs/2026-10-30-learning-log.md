```yaml

    sales: sales_train_evaluation.csv
    calendar: calendar.csv

```

脚本通过 `Path(__file__).resolve().parents[1]` 定位项目根目录，再读取配置、拼接数据路径。这样路径不依赖终端恰好从哪个目录启动。此处的 `parents[1]` 基于脚本位于 `scripts/` 的约定，迁移代码位置时需要相应调整。

配置负责可调整的路径和参数，代码负责处理规则。定义了 `preview_rows` 之后，读取销量时必须传给 `n_rows`，否则会意外读取并展开全量数据。

## 数据处理过程

### 宽表转换为长表

原销量表的一行表示一个商品在一家门店的完整历史，不是一天的样本。今天读取的五行包含五条序列，每条序列有 1,941 天。

六个标识列明确列出为 `id`、`item_id`、`dept_id`、`cat_id`、`store_id`、`state_id`。每日销量列通过 `d_` 前缀识别，使用 `DataFrame.unpivot` 展开：原列名进入 `d`，原销量值进入 `units_sold`。

将标识列明确写出，比依赖 `columns[:6]` 更稳妥。`unpivot` 返回新表，当前转换不需要先复制输入。

### 关联日历

日历表本来就是长表，不需要展开。完整读取日历后，选择 `d`、`date`、`wm_yr_wk`，按 `d` 左连接到销量长表。

销量表同一天有多条商品记录，日历表每个 `d` 只有一行，因此使用 `validate="m:1"` 检查右表键的唯一性，防止关联后行数增加。脚本检查了行数不变、日期不缺失和销量总和不变。

### 关联价格

价格由“哪家门店、哪个商品、哪一周”共同决定，因此关联键为：

```python
["store_id", "item_id", "wm_yr_wk"]
```

以日历关联结果为左表，与完整价格表左连接，并使用 `validate="m:1"`。三个同名键各保留一份，只增加 `sell_price`。完整价格表作为右表，不等于把右表所有记录都放入结果。

每次 `join` 都需要接住返回值。当前使用 `processed_sales`、`sales_with_calendar`、`sales_with_prices` 区分阶段，避免在旧表中选择尚未关联的字段。

`tests/test_inspect_m5.py` 使用两条虚拟商品序列、两个日期构造小表，并通过 `pytest.mark.parametrize` 验证四组对应关系：

目前每个参数案例直接构造小表，开销很低，尚未使用 fixture。多个测试需要共享同一套准备逻辑时，再提取 fixture。参数化负责列举不同案例，fixture 负责复用准备代码，两者用途不同。

## 今天遇到的问题

| 问题 | 原因与修正 |
| --- | --- |
| `calendar.columns["d"]` | `columns` 是列名列表，不是按列名取数据的字典。选若干列使用 `select`。 |
| 对日历表再次 `unpivot` | 日历已经一日一行，只需选择并关联所需字段。 |
| `index=6` 或 `on="d_"` | `index` 需要具体标识列，`on` 需要实际日销量列名，前缀不会自动匹配。 |
| `sell_price` 列不存在 | 打印了价格关联前的旧表，或没有保存 `join` 的返回结果。 |
| 单独写 `pl.col("date").str.to_date()` | 只是创建表达式，没有应用到 DataFrame；需要放进 `with_columns` 并接收结果。日期转换目前仍待完成。 |
| pytest 找不到 `scripts` | 测试导入时项目根目录不在搜索路径。当前从项目根目录使用 `python -m pytest` 运行。 |

日常运行测试：

```powershell

```

pytest 输出的 `rootdir` 是其项目与配置定位基准，不等同于 Python 已经把该路径加入模块搜索范围。后续迁移到可安装的源码包时，再统一规范源码导入。

## 面试复盘

**为什么将宽表转成长表？** 一行一条日观测后，可以按门店商品与日期排序，统一关联日历、周价格，并构造时序窗口。原宽表适合存储完整序列，长表更便于后续处理。

**为什么价格不能只按商品关联？** 同一商品在不同门店、不同周的价格可能不同。少用一个键，可能匹配多条价格、复制销量行，导致总量和训练样本失真。

**为什么使用左连接并检查多对一？** 左连接保留销量记录，让未匹配信息表现为缺失；多对一验证约束右表键唯一。再检查行数与总销量，确认关联没有扩大或丢失观测。

**价格缺失为什么不直接填零？** 缺少价格记录与商品免费不是同一业务含义。需要先检查缺失日期段和销量。用未来价格回填过去也可能引入预测时不可获得的信息。

**为什么用微型数据测试？** 预期结果可以人工核对，测试不依赖大文件和机器路径，也能快速定位字段对应错误。测试应验证处理规则，而不只验证程序能运行。

当前可以准确描述的阶段成果是：在 M5 五条门店商品序列上完成日销量整理与价格关联，使用守恒检查分析数据质量，并以四个参数化案例验证宽长表转换。尚不能声称完成全量生产管道、模型训练或预测效果提升。
