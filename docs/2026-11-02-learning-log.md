## 一、按固定日期划分数据集

### 配置与划分原则

将原先建议的“根据末尾日期倒推天数”改为在 YAML 中明确记录截止日期，使一次实验的范围固定，避免源数据追加后划分边界随之移动。

```yaml
split:
  train: train.parquet
  valid: valid.parquet
  test: test.parquet
  train_end: "2016-03-23"
  validation_end: "2016-04-22"
  test_end: "2016-05-22"
```

日期配置加引号，读取后通过 `date.fromisoformat()` 转为 Python 日期。预测目标仍然是未来 30 天，固定日期只是定义本次实验的数据划分方式。

所有门店商品序列使用相同时间边界，不随机按行划分：

| 集合 | 条件 | 日期范围 | 行数 |
| --- | --- | --- | ---: |
| train | `date <= train_end` | 2011-01-29 至 2016-03-23 | 376,200 |
| valid | `train_end < date <= validation_end` | 2016-03-24 至 2016-04-22 | 6,000 |
| test | `validation_end < date <= test_end` | 2016-04-23 至 2016-05-22 | 6,000 |

### 函数职责与返回方式

`scripts/split_m5.py` 中实现 `split_by_time()`：接收 DataFrame 和三个截止日期，先检查边界严格递增，再筛选并返回训练、验证、测试三个 DataFrame。

采用元组返回，调用方按固定顺序解包：

```python
train_sales, validation_sales, test_sales = split_by_time(
    sales, train_end, validation_end, test_end
)
```

函数不读取配置、不写文件、不访问 MinIO。`main()` 负责读取实验子集、转换配置日期、调用函数，并将三个结果保存到 YAML 指定的文件名。

### Polars 条件表达式

普通 Python 日期支持 `train_end < validation_end < test_end`。但包含 `pl.col("date")` 的筛选条件不能使用 Python 链式比较，需要拆成两个表达式，并分别加括号后用 `&` 连接：

```python
(pl.col("date") > train_end)
& (pl.col("date") <= validation_end)
```

这是因为 Polars 表达式代表整列运算，不能被 Python 当作单个布尔值判断。

实际检查三份文件均包含相同的 200 条门店商品序列。每条训练序列有 1,881 天，每条验证和测试序列各有 30 天，没有重复日期；三份数据的日期范围不重叠。

## 二、补充 wday，控制当前特征范围

### 原始日历与现有产物的区别

原始 `calendar.csv` 已有星期、月份、年份、事件和 SNAP 字段；原来的日历关联只保留 `d`、`date`、`wm_yr_wk`，因此 11 列 Parquet 没有星期字段。

当前决定只增加 `wday`：

```python
calendar_selected = calendar.select([
    "d", "date", "wm_yr_wk", "wday"
])
```

年份、月份从 `date` 派生；暂不扩展事件和 SNAP 特征，先完成基础预测流程，再通过模型结果和误差分析判断是否增加。事件特征是否采用属于实验范围选择，不能据此认定它对日销量没有影响。

`wm_yr_wk` 继续保留，当前周价格关联依赖这个 M5 周标识。它不能直接用普通年份和 ISO 周数拼接替代。

### 星期编码

M5 的星期编码是：

| 星期 | wday |
| --- | ---: |
| 周六 | 1 |
| 周日 | 2 |
| 周一 | 3 |
| 周二 | 4 |
| 周三 | 5 |
| 周四 | 6 |
| 周五 | 7 |

所以周末条件为 `wday` 属于 `[1, 2]`，不是 `wday >= 6`。使用已有字段时，必须先确认数据字典中的实际编码规则。

### 更新后的本地产物

重新生成了全量、抽样和三份划分文件。实际检查结果：

| 文件 | 行数 | 列数 |
| --- | ---: | ---: |

| m5_exp_sub.parquet | 388,200 | 12 |

## 三、日历特征函数

实际代码目录为 `etc/`，函数放在 `etc/features.py`，测试使用 `from etc.features import ...`。目前没有将目录改名为最初建议的 `etl/`。

实现 `add_calendar_features()`，一次性添加：

| 新列 | 计算方式 | 含义 |
| --- | --- | --- |
| year | `date.dt.year()` | 日历年份 |
| month | `date.dt.month()` | 日历月份 |
| is_weekend | `wday.is_in([1, 2])` | 是否周末，布尔值 |

函数使用 `return sales.with_columns(...)` 返回新表。只调用 `sales.with_columns(...)` 而不接收返回值，原变量仍指向原表，新增特征不会出现在最后返回结果中。

### 日历特征测试

用三行日期同时覆盖跨年、跨月与周末边界：

| date | wday | year | month | is_weekend |
| --- | ---: | ---: | ---: | --- |
| 2022-12-31 | 1 | 2022 | 12 | True |
| 2023-01-01 | 2 | 2023 | 1 | True |
| 2023-01-02 | 3 | 2023 | 1 | False |

逐列比较具体列表，而不是只检查新列数量。测试数据的 `date` 与 `wday` 保持一致；函数目前直接信任输入的星期编码，没有额外校验二者是否匹配。

## 四、分组滞后销量特征

### 参数与实现

实现 `add_lag_features(sales, lags)`。`lags` 是滞后步数列表，例如 `[1, 7, 28]` 表示生成 `lag_1`、`lag_7`、`lag_28`；列表中不是历史销量值。

执行顺序：

1. 按 `store_id`、`item_id`、`date` 升序排序。
2. 对每个 lag 构造表达式：销量 `shift(lag)`，并使用 `over(["store_id", "item_id"])` 将运算限定在每条销售序列内部。
3. 收集所有表达式，一次性调用 `with_columns()` 添加各列。

日期连续且每个门店商品每天一行时，向后移动一行对应一天。本次实验数据已核对日期完整，但函数本身目前没有新增日期缺口检查。

### 为什么循环中只剩最后一个 lag

最初每轮都执行 `processed_sales = sorted_sales.with_columns(...)`。虽然 alias 名称不同，但每次都从没有任何 lag 的原表出发，随后重新给同一个 Python 变量赋值，最终只留下最后一轮生成的表。

这不是不同 alias 的列名相互覆盖。可行方式有两种：基于上一轮结果继续添加，或收集全部表达式后统一添加。当前采用后者。

### 缺失历史与分组边界

序列开头没有足够历史时保留 null，Python 测试预期值写 `None`，不能直接写 `null`。零销量是有效观测，不能与缺失历史混为一谈。

lag 测试采用同一家门店的两个商品，每个商品三天：

| 商品 | 原销量 | lag_1 | lag_2 |
| --- | --- | --- | --- |
| A | `[2, 0, 5]` | `[None, 2, 0]` | `[None, None, 2]` |
| B | `[10, 20, 30]` | `[None, 10, 20]` | `[None, None, 10]` |

对整列列表进行精确断言，确认两个 lag 同时存在、零销量保留、各商品开头为空，且 B 不会接到 A 的最后一个销量值。当前测试输入本身有序，尚未专门覆盖乱序输入和同商品跨门店的案例。

## 七、面试复盘要点

**为什么用固定日期而不是随机划分？** 预测任务存在时间顺序，训练、验证和测试使用统一且可追溯的日期边界，避免把未来样本用于过去的评估。

**为什么只补充 wday？** 先控制特征范围，复用原始数据中明确的星期编码，年份月份从日期生成。事件与 SNAP 是否有增益，需要后续实验判断，当前不提前扩大处理逻辑。

**为什么 lag 必须分组并排序？** 排序定义历史顺序，分组确保历史来自同一家门店的同一个商品，避免将其他序列的销量混入输入。

**为什么开头的空值不填零？** 空值表示没有足够历史，零表示观察到销量为零，二者含义不同。

**测试为什么比较具体日期和具体 lag 值？** 行数或总和相等仍可能隐藏边界分错、值错位和跨组串值；可人工核对的具体结果能够直接验证这些规则。

**今天能够准确描述的成果是什么？** 已完成固定时间切分与基础历史特征函数，并通过边界和分组测试；尚未将这些特征投入正式训练，也没有模型效果提升的结论。
